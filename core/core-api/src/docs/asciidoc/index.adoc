Auth-Service API 문서입니다.

|===
|목적 |권장 API
|이메일 회원가입 |`POST /api/v1/auth/email/signup`
|이메일 로그인 |`POST /api/v1/auth/email/login`

|전화번호 회원가입 |`POST /api/v1/auth/phone/signup`

|OAuth2 시작 |`GET /api/v1/auth/oauth2/{provider}/authorize-url`
|===

==== 프론트 구현 체크리스트

- 로그인/토큰 갱신/로그아웃 시 `X-Device-Id`를 동일 값으로 유지
- 보호 API 호출 시 `Authorization: Bearer {accessToken}` 전달

==== 샘플 요청

[source,http]
----
POST /api/v1/auth/email/signup
Content-Type: application/json

{
  "email": "user@example.com",
  "password": "P@ssw0rd!",
  "name": "홍길동",
  "nickname": "gildong",
  "gender": "MALE"
}
----

[source,http]
----
POST /api/v1/auth/token/refresh
Content-Type: application/json
X-Device-Id: web-chrome-001

{
  "refreshToken": "..."
}
----

== Auth API (Current)

신규 인증 API는 아래 3개 로그인 수단을 제공합니다.

- 이메일 로그인: `POST /api/v1/auth/email/login`
- 아이디 로그인: `POST /api/v1/auth/id/login`
- 휴대폰 로그인: `POST /api/v1/auth/phone/login`

회원가입 정책:

- 이메일 회원가입(`POST /api/v1/auth/email/signup`): 휴대폰 인증 없이 가입 가능
- 아이디 회원가입(`POST /api/v1/auth/id/signup`): 휴대폰 인증 필수
- 휴대폰 회원가입(`POST /api/v1/auth/phone/signup`): 휴대폰 인증 필수

토큰:

- 토큰 갱신: `POST /api/v1/auth/token/refresh`

참고:

- 기존 `/api/v1/auth/local/*` 경로는 하위 호환 목적으로 유지됩니다.
- 상세 처리 흐름은 `docs/api/README_AUTH_API.md`를 참고하세요.
