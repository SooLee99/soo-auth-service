=== Frontend Quick Start (권장)

신규 클라이언트는 **멀티서비스 경로**를 사용하세요.

- 경로 패턴: `/api/v1/services/{serviceCode}/...`
- 예시 serviceCode: `DEFAULT`, `SHOP`, `CRM`
- `serviceCode`는 서버에서 형식/등록/활성 상태를 검증합니다.

[cols="1,3"]
|===
|목적 |권장 API
|회원가입 |`POST /api/v1/services/{serviceCode}/auth/local/signup`
|토큰 갱신 |`POST /api/v1/services/{serviceCode}/auth/local/token/refresh`
|로그아웃 |`POST /api/v1/services/{serviceCode}/auth/local/logout`
|탈퇴 |`POST /api/v1/services/{serviceCode}/auth/local/withdraw`
|OAuth2 시작 |`GET /api/v1/services/{serviceCode}/auth/oauth2/{provider}/authorize-url`
|===

==== 프론트 구현 체크리스트

- 모든 요청에서 `serviceCode`를 URL Path에 포함
- 로그인/토큰 갱신/로그아웃 시 `X-Device-Id`를 동일 값으로 유지
- 보호 API 호출 시 `Authorization: Bearer {accessToken}` 전달
- `409` 응답에서 서비스 상태/서비스 코드 오류(`SERVICE_INACTIVE`, `NOT_FOUND`) 처리

==== 샘플 요청

[source,http]
----
POST /api/v1/services/DEFAULT/auth/local/signup
Content-Type: application/json

{
  "email": "user@example.com",
  "password": "P@ssw0rd!",
  "name": "홍길동",
  "nickname": "gildong",
  "gender": "MALE",
  "phoneNumber": "+82 10-1234-5678"
}
----

[source,http]
----
POST /api/v1/services/DEFAULT/auth/local/token/refresh
Content-Type: application/json
X-Device-Id: web-chrome-001

{
  "refreshToken": "..."
}
----

=== 서비스 등록
* 관리자 권한이 필요합니다.
* 같은 `serviceCode`가 이미 있으면 `409 DUPLICATE_SERVICE_CODE`
* `serviceCode` 규칙: `^[A-Z0-9][A-Z0-9_-]{1,63}$`

[source,http]
----
POST /api/v1/auth/admin/services
Authorization: Bearer {adminAccessToken}
Content-Type: application/json

{
  "serviceCode": "SHOP",
  "serviceName": "Shopping Service"
}
----

'''

=== 서비스 목록 조회
* 관리자 권한이 필요합니다.

[source,http]
----
GET /api/v1/auth/admin/services?page=0&size=20
Authorization: Bearer {adminAccessToken}
----

'''

=== 서비스 비활성화(삭제 아님)
* 관리자 권한이 필요합니다.
* 물리 삭제가 아니라 `INACTIVE` 상태 전환입니다.
* `DEFAULT` 서비스는 비활성화할 수 없습니다.
* 활성 멤버십이 있으면 비활성화할 수 없습니다. (`409 SERVICE_HAS_ACTIVE_MEMBERSHIPS`)

[source,http]
----
POST /api/v1/auth/admin/services/SHOP/deactivate
Authorization: Bearer {adminAccessToken}
----
